# Team Gold Star Git Standards Policy

Version 1.1  
Last updated: 9/14/26

# General Guidelines

* ALL development should be done on branches and any updates to the main branch should be done through merge requests  
* Merge requests should be reviewed by at a minimum one person before being merged.  
* Merge conflicts should be primarily resolved by the branch owner and secondarily resolved by the creator of the conflict.

# Branch Guidelines

* The team will be developing on their branches using conventional branch standards.  
  * [https://conventionalbranch.org/\#summary](https://conventionalbranch.org/#summary)   
* Branches should be named like so: \[conventional prefix\]/\[number\]-\[branch-name\]  
* Development on a branch should only be done by one developer.  
  * If changes by another developer should be added to a branch a merge should be done.  
* Commits on branches should be done using conventional commits (lightly enforced).  
  * [https://www.conventionalcommits.org/en/v1.0.0/\#specification](https://www.conventionalcommits.org/en/v1.0.0/#specification)  
  * Mainly include the prefixes like “feat:” and “bug”

# PR Guidelines

* Pull requests should be reviewed by at a minimum 1 person other than the primary developer of the PR.  
* If changes are made to code another developer has developed, that developer should review the changes.  
  * Use git blame to see who made the most recent changes.  
* Pull requests should be reviewed within a week of being opened, if the pull request is not reviewed by that time it will be reviewed during the next weekly meeting.  
  * See last updated pull requests.  
  * Ping Wesley if this needs to be done.  
* Pull requests should be appropriately tagged.  
* The ticket in which a PR is being made for should be linked to the PR.  
* If there are more than 5 commits on a pull request they should be squashed.  
* Always squash merge.
